## 검증

기존 컴퓨터에서 임시 폴더에 `requirements.txt`를 만들고 “승인된 재시도 횟수”를 읽게 했다. 샌드박스 안 첫 호출은 90초가 지나 중단됐다. 사용자 환경의 두 재시도는 모두 종료 코드 0이고 턴 사용량이 있었지만 정확한 `7`을 반환하지 않았다. 마지막 재시도에는 완료된 `agent_message`만 있었고 파일 읽기 도구 이벤트가 없었다. 정답을 프롬프트에 직접 넣은 별도 대조 문항은 통과했다. 이 네 번은 준비 점검이며 실패 원인, 기능별 실패율, 토큰 절감률을 보여 주는 본시험 자료로 쓰지 않는다.

`python .mycodex/mycodex.py compression doctor --client codex --target . --json`은 `not_ready`를 반환했다. `compression prepare --target .`의 dry-run은 `planned`, `changed: false`였다. 해당 세션에서 Langfuse에 올린 데이터는 없다.

## 다음 행동

1. **자료 이동.** 개발 저장소를 통째로 옮기면 아래 재개 문구를 사용할 수 있다. 최소 구성은 **이 인계, 설계안, 위 0.5.1 ZIP**이다. 최소 구성에서는 인계와 설계안을 파일명으로 직접 열고 ZIP 안의 `kit/integrations/billion-context/README.md`를 참고한다. 개발 문서와 최신 로컬 ZIP은 배포 ZIP 내부나 기존 Git 커밋에 자동 포함되지 않는다.
2. **공통 작업 사본 준비.** 제품 소스·패키지 밖에 실험 폴더를 두고 모델 권한으로 정답·다른 조건·이전 로그를 읽을 수 없는지 표식으로 확인한다. Python 3.11 이상과 실제 Codex 실행 파일·로그인을 확인한다. 압축에는 Node 20 이상과 npm도 필요하다. 합성 사본들에는 설치 전에 동일한 실험용 `.codex/config.toml`을 둔다. 예를 들어 Luna 기본 문맥 설정을 쓸 때에는 Astra의 100만/85만 값을 복사하지 않는다. 실제 적용값도 양쪽이 같은지 확인한다. 조건별 파일·해시, 실제 바이너리, 문맥 창·내장 자동 압축, 샌드박스·신뢰·hooks·MCP·스킬을 설계안의 비교표와 대조한다. 제품 설정은 보존한다.
3. **도구 사전 점검.** 아래는 별도 합성 폴더에서 실행하는 Windows PowerShell 예다. `codex.exe`가 PATH에 없거나 shim이면 먼저 실제 실행 파일의 절대 경로를 현재 프로세스의 `MYCODEX_CODEX_EXE`에 지정한다. 인라인 정답, 임의 정수가 담긴 `requirements.txt` 읽기, 수정·테스트를 순서대로 점검한다. JIT는 앞·중간·끝에 표식을 넣은 긴 출력도 시험해 화면 출력과 모델용 반환 구간을 대조한다. 대응 범위를 확인하지 못하면 JIT 열람량 지표만 보류한다. 아래는 읽기용이며 수정 과제에서는 양쪽 모두 `workspace-write`를 사용한다.

```powershell
$codexExe = if ($env:MYCODEX_CODEX_EXE) { (Resolve-Path -LiteralPath $env:MYCODEX_CODEX_EXE -ErrorAction Stop).Path } else { (Get-Command codex.exe -CommandType Application -ErrorAction Stop | Select-Object -First 1).Source }
$env:MYCODEX_CODEX_EXE = $codexExe
& $codexExe --version
Get-FileHash -LiteralPath $codexExe -Algorithm SHA256
$lunaArgs = @('-m','gpt-6-luna','-c','model_reasoning_effort=low','-c','plan_mode_reasoning_effort=low','--disable','multi_agent','-c','agents.enabled=false','--disable','memories')
& $codexExe --no-daemon exec @lunaArgs --sandbox read-only --skip-git-repo-check --json 'requirements.txt에서 승인된 횟수를 읽고 정수 하나로 답하세요.'
```

4. **Cloud 계측 점검.** Langfuse endpoint와 키는 평가자의 로컬 수집기에 설정한다. 첫 실행의 JSONL에서 `thread.started.thread_id`를 확인하고 같은 스레드에서 두 번째 턴을 연다. 아래 `Read-Host`에는 그 스레드 ID를 입력한다. 두 시점의 원천 사용량·CLI 이벤트·Cloud 사용량과 Score를 대조한다. 누계형이면 스레드별 종료 누계에서 시작 직전 누계를 뺀 값을 기록한다. 중복 전송, 사용량 이벤트 없는 0, 리셋·음수 차분을 확인한다. 누락은 해당 지표 결측이다.

```powershell
$trialThread = Read-Host '첫 실행의 thread_id'
& $codexExe --no-daemon exec @lunaArgs --sandbox read-only --skip-git-repo-check resume --json $trialThread '앞서 확인한 횟수를 다시 답하세요.'
```

5. **일반 CLI에서 실패부터 재현.** 과제·버전·정답표·시도 횟수를 고정하고 JIT, 인계, billion-context를 모두 끈 상태에서만 먼저 실행한다. 인계 후보의 첫 메시지에는 업무와 순서만 쓰고 존재하지 않는 인덱스·인계는 언급하지 않는다. 설계 제안은 새 실행 3회 중 2회 이상 같은 유형의 실패 재현이다. 모든 시도와 채점 근거·trace ID를 남긴다. 정상 환경에서 정답·재개·완주 실패가 재현된 후보만 채택한다. 채택 과제가 없으면 해당 기능은 보류한다.
6. **채택 과제에서만 새 OFF/ON 비교.** JIT는 공통 원본만으로 최신 승인 근거를 판별할 수 있게 하고 ON 인덱스에는 경로·용도만 둔다. 인계는 공통 사본에서 초기화와 실제 `$project-init` 조사를 마치고 `ready` 및 `python .mycodex/mycodex.py validate --target . --strict --json` 통과를 확인한 뒤 분기한다. 새 스레드로 재개하고 ON에서 인계와 함께 변경된 지침·결정 문서도 기록한다. 평가는 인계 워크플로 전체를 포함한다.
7. **압축 분기.** 공통 설치 사본을 복제해 일반·경유 조건의 파일·유효 설정을 맞춘다. 아래는 합성 프로젝트 루트에서의 예다. 별도 실험 런타임을 쓰는 경우 모든 압축 명령에 같은 `--runtime` 경로를 지정한다. 기존 런타임이 다른 CLI를 가리키면 일치하는 별도 런타임을 준비한다. 경유기는 자체적으로 `--no-daemon`을 전달한다. 이 경로에서도 4단계의 두 턴과 차분을 검증한다.

```powershell
python .mycodex/mycodex.py compression doctor --client codex --target . --json
python .mycodex/mycodex.py compression prepare --target .
python .mycodex/mycodex.py compression prepare --target . --apply
$diag = python .mycodex/mycodex.py compression doctor --client codex --target . --json | ConvertFrom-Json
if (-not $diag.installed) { throw '실험 런타임 준비 상태를 확인하세요.' }
$owner = Get-Content -Raw -Encoding utf8 -LiteralPath (Join-Path $diag.runtime 'owner.json') | ConvertFrom-Json
if ((Resolve-Path -LiteralPath $owner.tools.codex -ErrorAction Stop).Path -ne $codexExe) { throw '일반 CLI와 런타임에 고정된 CLI의 경로가 다릅니다.' }
python .mycodex/mycodex.py compression codex --target . --apply -- exec @lunaArgs --sandbox read-only --skip-git-repo-check --json 'requirements.txt에서 승인된 횟수를 읽고 정수 하나로 답하세요.'
$biliThread = Read-Host '바로 위 경유 실행의 thread_id'
python .mycodex/mycodex.py compression codex --target . --apply -- exec @lunaArgs --sandbox read-only --skip-git-repo-check resume --json $biliThread '앞서 확인한 횟수를 다시 답하세요.'
```

8. **채점·동결.** 정상 환경에서 기능 자체가 일으킨 중단은 해당 조건의 완주 실패로 센다. 외부 장애·원인 미확정은 보류하고 계측만 누락되면 확인 가능한 산출물은 채점한다. 압축 미발동도 전체 쌍에 남기되, 압축·복원 기여를 주장할 때는 그 실행의 블록·복원 근거를 확인한다. 본시험 전 독립 과제군 최소 수와 판정식을 동결하고, 설계안의 판정표대로 대상 실패율과 전체 성공률을 함께 비교한다.

## 재확인 사항

- 작성 당시 개발 저장소의 HEAD는 `431c8fabab1404a11315cfd725c9846c35eaa9bd`였다. 이전 0.5.1 설정 변경은 작업 트리에 있었고 배포 폴더·ZIP도 미추적 상태였다. 새 PC에서는 커밋만 같다는 이유로 동일 버전이라고 가정하지 말고 ZIP 해시와 설치 manifest를 확인한다.
