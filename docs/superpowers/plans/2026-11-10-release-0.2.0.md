# 0.2.0 Distribution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 이번 업데이트 전체를 0.2.0 배포 폴더와 ZIP에 반영하고, 배포본만으로 설치되는 것을 확인한다.

**Architecture:** 설치 자산 목록을 허용 목록으로 사용해 `README.md`, `CHANGELOG.md`, `kit/`만 배포한다. 같은 파일 목록으로 폴더와 결정적인 ZIP을 만들며 기존 버전과 사용자 파일은 보존한다.

**Tech Stack:** Python 3.11+ 표준 라이브러리, unittest, ZIP.

**Spec:** [HTML 스킬 설계](../specs/2026-11-10-human-html-design.md), [프로젝트 설정 설치 설계](../specs/2026-11-10-project-config-design.md). 사용자는 후속 요청으로 이번 변경 전체의 배포본 생성까지 범위를 확장했다.

## Global Constraints

- 버전은 `kit/mycodex_lib/model.py`의 `KIT_VERSION`인 0.2.0을 사용한다.
- 기존 0.1.x 배포본·활성 설정·사용자 파일을 보존한다.
- 개발 문서·자체 설치본·개인 설정·생성 HTML은 배포본에 넣지 않는다.
- 배포 경로와 변경 이력을 최종 버전에 맞춘다. 외부 게시 위치가 지정되지 않았으므로 기존 프로젝트의 `dist/` 배포 방식을 따른다.

## Review Focus

- 새 스킬·저장 도구·config 템플릿·축약된 정책이 모두 같은 스냅샷이어야 한다.
- 배포본의 README에는 개발 저장소 전용 경로나 링크가 남지 않아야 한다.
- 같은 버전의 재생성은 동일 결과를 유지하고, 수정된 산출물은 덮어쓰지 않아야 한다.
- ZIP만 풀어 설치할 때 새 설정 생성과 기존 설정 보존, HTML 저장이 모두 동작해야 한다.

## 실제 실행 결과

- 새 배포 검사 4개를 먼저 실행해 빌드 도구가 없어서 실패하는 것을 확인했다. 도구 구현 후 네 검사 모두 통과했다.
- `python tools/build_release.py`로 `dist/MyCodexSetting-0.2.0/`와 `dist/MyCodexSetting-0.2.0.zip`을 생성했다. 같은 명령을 다시 실행해 기존 산출물을 보존하며 성공하는 것을 확인했다.
- 배포 파일은 23개다. README, CHANGELOG와 설치 자산 목록의 21개 파일만 포함한다. ZIP의 모든 파일 바이트가 배포 폴더와 일치하고, 21개 kit 자산은 원본 및 자체 설치본과 일치한다.
- ZIP 단독 설치 시험에서 dry-run 무변경, 새 config 생성, 사용자 설정 변경 후 재설치 보존, 설치된 HTML 저장 도구 실행과 fixture의 strict 구조 검증을 확인했다. fixture의 ready 전환은 설치 시험을 위한 것으로 실제 앱 개발 완료를 의미하지 않는다.
- 최종 전체 명령 `python -X utf8 -B -m unittest discover -s tests -v` — 28 tests, 38.986s, OK.
- 현재 설치본 `python -B .mycodex/mycodex.py validate --target . --strict --json` — `{"ok": true, "findings": []}`. `git diff --check`도 통과했다.
- 기존 0.1.0~0.1.2 배포 폴더·ZIP과 활성 `.codex/config.toml`은 Git diff로 무변경을 확인했다.
- ZIP 크기: 31,263 bytes. SHA-256: `b4567490560fca8f383b0f8cded6c0385966ebf914127c06d74bd142d3f0c126`.
