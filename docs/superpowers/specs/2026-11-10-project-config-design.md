# 프로젝트 config.toml 설치

## 요청과 적용 방식

사용자는 현재 설치 자산에 `config.toml`을 포함하도록 요청했다. 기존 파일 보존과 dry-run 설치 흐름을 따른다.

- 현재 저장소의 `.codex/config.toml` 값을 `kit/templates/config.toml`의 초기값으로 사용한다. 현재 파일에는 비밀 값이나 사용자 경로가 없음을 확인했다. 이후 설치 기본값의 원본은 이 템플릿이다.
- 대상에 `.codex/config.toml`이 없으면 생성한다. 기존 파일은 내용에 관계없이 보존하며 자동 병합·덮어쓰기는 제공하지 않는다.
- 배포 템플릿은 `.mycodex/templates/config.toml`에도 설치해 자산 검증에 포함한다. 실제 `.codex/config.toml`은 사용자가 조정할 수 있으므로 해시 고정 자산으로 관리하지 않는다.
- 설치 전 변경안에 생성/보존을 표시한다. 경로 이탈과 파일/디렉터리 충돌은 기존 전체 사전 검사에서 차단한다.
- 사용자 전역 설정과 현재 저장소의 활성 `.codex/config.toml`은 수정하지 않는다. 프로젝트 신뢰나 현재 세션의 설정 적용 여부를 대신 변경하지 않는다.
- 기존 배포 ZIP은 보존한다. 변경은 0.2.0 개발 원본에 포함한다.

## 선택 근거

현재 설정을 템플릿으로 설치하면 요청한 초기 세팅을 반복 사용할 수 있다. 빈 파일이나 주석만 있는 예시는 설정값을 다시 입력해야 하므로 채택하지 않는다. 실제 설정을 고정 해시 자산으로 취급하면 정상적인 사용자 조정이 충돌이 되므로 템플릿과 생성 파일의 소유권을 구분한다.

## 검증 범위

dry-run 무변경, 새 파일 생성, 기존 설정 보존, 사용자 조정 후 재설치·구조 검증, 잘못된 대상 경로 사전 검사와 템플릿 무결성을 실제 CLI로 확인한다. TOML 문법과 설치 동작을 검증하며 실제 Codex 세션의 설정 재로딩은 별도 범위다.
