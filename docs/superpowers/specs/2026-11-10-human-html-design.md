# 사람을 위한 HTML 문서 스킬 설계

상태: 승인됨 — 2026-11-10 사용자 승인

## 목적과 확인된 요구사항

- 사용자가 직접 적은 주제에 대해 사람이 읽고 이해하기 쉬운 HTML 문서를 만든다.
- 생성된 HTML은 일반 개발 작업의 탐색·검색·원본 참조에서 제외한다.
- 사용자는 파일 접근 권한 자체를 차단할 필요는 없다고 확인했다.
- HTML 작성 과정의 토큰 사용과 저장 후 다시 읽는 컨텍스트 사용을 구분한다. 토큰 사용량 0이나 접근 차단을 보장하지 않는다.

## 검토한 방식

1. **일반 탐색에서 제외 — 사용자 선택.** 전용 폴더, 검색 제외 규칙, 작업 지침으로 사람이 읽는 산출물을 분리한다. 기존 Python 설치 도구와 문서 탐색 정책에 연결할 수 있다.
2. **파일 접근 권한 차단.** 별도 권한·저장 통로를 구성해야 한다. 사용자가 이 수준은 필요하지 않다고 확인했으므로 범위에서 제외한다.

## 제안하는 사용 방식

스킬 이름은 `human-html`로 제안한다. 사용자가 명시적으로 호출하고 뒤에 주제를 적었을 때만 실행한다.

```text
$human-html
현재 프로젝트에서 개발하고 있는 앱 서비스의 구조를 html 문서로 정리해줘.
```

- 특정 문서 종류로 제한하지 않는다. 서비스 구조, 동작 흐름, 변경 설명 등 사용자가 적은 주제에 맞춘다.
- 주제가 없으면 필요한 주제만 질문한다. 기존 예시를 기본 주제로 대신 실행하지 않는다.
- AGENTS → 컨텍스트 인덱스 → 관련 원본 순서로 필요한 자료만 조사한다.
- 실제 코드·문서로 확인한 내용과 추론·계획·미확인 내용을 구분한다.
- 주제에 맞는 설명, 표, 도식을 사용한다. 목차와 읽기 순서를 정리하고 모바일 화면과 인쇄에서도 읽을 수 있게 한다.
- 외부 서비스 없이 브라우저에서 열리는 독립 HTML을 기본으로 한다. 설명에 필요한 CSS·도식은 파일 내부에 포함한다.

## 산출물 보관과 읽기 예외

- 저장 위치는 프로젝트 루트의 `.human-docs/`로 제안한다. 문서를 처음 만들 때 필요한 폴더와 제외 규칙을 준비한다.
- 파일명에는 시각과 주제를 넣고 기존 문서를 자동으로 덮어쓰지 않는다.
- 해당 폴더 내부의 `.gitignore`와 `.ignore`로 HTML을 Git 및 ignore 규칙을 따르는 검색에서 제외한다. `.ignore`는 Git이 없는 폴더의 검색도 지원하기 위한 구현 선택이다. 기존 루트 제외 파일은 보존한다.
- AGENTS에는 공통 제외 지침을 두고, 컨텍스트 정책에는 일반 탐색 제외와 인덱스 갱신 예외만 둔다. 생성·검증·출력 및 ignore를 무시하는 검색의 상세 규칙은 `human-html` 스킬에서 관리한다. 사용자 후속 승인에 따라 컨텍스트 정책의 별도 HTML 절은 두지 않는다.
- HTML은 컨텍스트 인덱스의 원본으로 등록하지 않고, 세션 인계의 근거로 사용하거나 본문을 복사하지 않는다. 이 규칙은 일반적인 문서 생성 시 인덱스를 갱신하는 규칙의 예외다.
- 명시적인 HTML 생성·수정 요청을 수행하고 결과를 검증할 때만 해당 산출물에 접근할 수 있다. 다음 일반 개발 작업에서는 다시 탐색 대상에서 제외한다.
- 결과 보고에는 생성 경로와 짧은 설명, 실제 검증 결과만 남긴다. HTML 전문이나 대량의 DOM·도구 출력을 채팅으로 돌려받지 않는다.

## 기존 프로젝트와의 연결

- `kit/skills/human-html/`에 스킬과 명시적 호출 정책을 추가하고 설치 자산 목록·구조 검증에 연결한다.
- 파일 저장과 제외 규칙 준비에 반복되는 처리가 필요하면 Python 표준 라이브러리 보조 도구로 제공한다. 도구는 HTML 본문을 출력하지 않는다.
- AGENTS 템플릿, 컨텍스트 정책, `project-init`과 `session-handoff`에도 동일한 제외 기준을 반영한다. 기존 사용자 지침은 보존한다.
- 이 저장소에 설치된 사본과 사용 설명서도 맞춘다. 기존 버전의 배포 ZIP과 폴더는 역사적 산출물로 보존한다.
- 다른 프로젝트의 기존 설치본을 자동으로 업그레이드하는 기능은 추가하지 않는다.

## 확인할 결과

- 기존 CLI 회귀 테스트와 설치본의 strict 구조 검증을 통과한다.
- 새 설치에 스킬이 포함되고 재설치가 기존 파일을 보존한다.
- 사용자가 지정한 주제가 없는 경우와 있는 경우의 스킬 동작을 확인한다. 실제 에이전트 실행과 구조 검사 결과를 구분한다.
- 생성한 HTML이 브라우저에서 읽히고, 일반 검색에서 본문이 제외되며, 인덱스·인계의 원본으로 편입되지 않는지 확인한다.
- 저장 도구를 추가하면 경로 이탈·기존 파일 덮어쓰기·본문 출력 방지처럼 실제 파일 동작을 검증한다.
